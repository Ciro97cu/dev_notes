# ES2025 (ES16)

La sedicesima edizione è ricca e orientata all'ergonomia. Porta gli **iterator helper** (i metodi funzionali di trasformazione, finalmente sugli iteratori e in forma *lazy*), i **metodi insiemistici** di `Set`, gli **import attributes** con i moduli JSON, e una serie di raffinamenti su Promise, RegExp e tipi numerici.

---

## Iterator helpers

Prima di ES2025, per usare `map`, `filter` e simili su un iteratore (per esempio quello prodotto da un generator o da `Map.keys()`) bisognava prima materializzarlo in un array con lo spread `[...it]` — perdendo la **pigrizia** e sprecando memoria su sorgenti grandi o infinite. ES2025 aggiunge questi metodi direttamente su `Iterator.prototype`, in versione **lazy**: elaborano un elemento alla volta, su richiesta, senza costruire array intermedi.

```js
function* naturali() { let n = 1; while (true) yield n++; }  // infinito

const primiTre = naturali()
    .map(n => n * n)      // lazy
    .filter(n => n % 2)   // lazy
    .take(3)              // prende solo i primi 3
    .toArray();           // [1, 9, 25] — materializza solo ora
```

I metodi disponibili su `Iterator.prototype`:

- **Trasformazione lazy** (restituiscono un nuovo iterator): `map`, `filter`, `take(n)`, `drop(n)`, `flatMap`.
- **Consumo** (esauriscono l'iterator e restituiscono un valore): `reduce`, `toArray`, `forEach`, `some`, `every`, `find`.

`Iterator.from(iterable)` avvolge un qualsiasi iterable (o iterator) in un iterator che espone questi helper, così da poterli usare anche su sorgenti che non li hanno nativamente.

```js
Iterator.from(["a", "b", "c"])
    .map((v, i) => `${i}:${v}`)
    .toArray();   // ["0:a", "1:b", "2:c"]
```

Il vantaggio chiave rispetto ai metodi degli array è la valutazione pigra: `take(3)` su un generator infinito calcola solo i tre elementi necessari, dove `[...gen].slice(0, 3)` girerebbe all'infinito.

## Metodi di `Set`

`Set` guadagna i metodi che implementano le classiche operazioni della teoria degli insiemi, prima da scrivere a mano. Restituiscono un nuovo `Set` (i primi quattro) o un booleano (gli ultimi tre), senza mutare gli originali.

```js
const a = new Set([1, 2, 3]);
const b = new Set([2, 3, 4]);

a.union(b);                // Set {1, 2, 3, 4}
a.intersection(b);         // Set {2, 3}
a.difference(b);           // Set {1}       — in a ma non in b
a.symmetricDifference(b);  // Set {1, 4}    — in a o b ma non in entrambi

a.isSubsetOf(b);           // false
a.isSupersetOf(new Set([1, 2])); // true
a.isDisjointFrom(new Set([9])); // true — nessun elemento in comune
```

L'argomento non deve essere per forza un `Set`: basta che sia *set-like*, cioè che esponga `size`, un metodo `has()` e un metodo `keys()` (condizione soddisfatta anche da `Map`, per esempio).

## Import attributes e moduli JSON

Gli **import attributes** permettono di allegare metadati a un import con la clausola `with { ... }`. Il caso d'uso principale sono i **moduli JSON**: importare un file JSON direttamente come modulo, dichiarandone il tipo (obbligatorio, per ragioni di sicurezza — impedisce che un server serva codice al posto di dati).

```js
/* import statico di un file JSON */
import config from "./config.json" with { type: "json" };
config.versione;   // usa il JSON come oggetto

/* import dinamico */
const dati = await import("./dati.json", { with: { type: "json" } });
```

> [!info]
> Una precedente proposta usava la parola chiave `assert` (*import assertions*, `assert { type: "json" }`), che è stata **ritirata** e non è mai entrata in un'edizione finale. La forma standardizzata da ES2025 usa `with`. Se si incontra `assert` in codice o tutorial più vecchi, è sintassi obsoleta.

## `RegExp.escape()`

Una funzione statica che *neutralizza* i caratteri speciali di una stringa, rendendola sicura da inserire **letteralmente** dentro una regex costruita dinamicamente. Risolve un problema di sicurezza e correttezza vecchio quanto le regex dinamiche: interpolare input non fidato in un pattern senza escape lo espone a comportamenti indesiderati (una `.` dell'utente matcherebbe qualsiasi carattere).

```js
const inputUtente = "a.b*c";
const re = new RegExp(RegExp.escape(inputUtente));   // cerca esattamente "a.b*c"
RegExp.escape(inputUtente);   // "a\\.b\\*c" — i metacaratteri sono neutralizzati
```

Prima si ricorreva a una regex di escape scritta a mano (`str.replace(/[.*+?^${}()|[\]\\]/g, "\\$&")`), soggetta a dimenticanze; `RegExp.escape` è la versione ufficiale e completa.

## Raffinamenti su RegExp

Due aggiunte più piccole alle espressioni regolari.

**RegExp modifiers** (modificatori inline): permettono di attivare o disattivare un flag **solo per una parte** del pattern, con la sintassi `(?flag:...)` o `(?-flag:...)`. Sono ammessi esclusivamente i flag `i`, `m` e `s`.

```js
/* case-insensitive solo per "hello", il resto è case-sensitive */
/(?i:hello) WORLD/.test("HELLO WORLD");   // true
/(?i:hello) WORLD/.test("HELLO world");   // false — WORLD resta case-sensitive
```

**Duplicate named capture groups**: lo stesso nome di gruppo può ora comparire in **alternative diverse** dello stesso pattern (prima era un errore). Utile quando lo stesso dato può presentarsi in formati alternativi.

```js
/* l'anno può stare prima o dopo: stesso nome in entrambe le alternative */
const re = /(?<anno>\d{4})-\d\d|\d\d-(?<anno>\d{4})/;
"2026-08".match(re).groups.anno;   // "2026"
"08-2026".match(re).groups.anno;   // "2026"
```

## `Float16Array` e half-precision

ES2025 aggiunge il supporto ai float a **16 bit** (mezza precisione), usati soprattutto in ambito grafico (WebGPU), machine learning e dove serve dimezzare l'occupazione di memoria rispetto ai `Float32Array`.

```js
const f16 = new Float16Array([1.5, 2.5, 3.5]);   // nuovo TypedArray

Math.f16round(3.14159);   // arrotonda al più vicino float16 rappresentabile

const dv = new DataView(new ArrayBuffer(2));
dv.setFloat16(0, 1.5);    // scrittura half-precision
dv.getFloat16(0);         // 1.5
```

`Math.f16round(x)` è l'analogo a 16 bit di `Math.fround` (che arrotonda a float32).

## `Promise.try()`

Esegue una funzione e ne avvolge l'esito in una Promise, **uniformando** i tre possibili comportamenti: valore restituito in modo sincrono, eccezione lanciata in modo sincrono, o Promise restituita. È utile quando si riceve una funzione che *potrebbe* essere sincrona o asincrona e si vuole trattarla in modo uniforme, catturando anche un eventuale `throw` sincrono nella catena `.catch()`.

```js
Promise.try(() => puòLanciareOppureRestituirePromise())
    .then(risultato => usa(risultato))
    .catch(err => gestisci(err));   // cattura sia i throw sincroni sia i reject
```

Senza `Promise.try`, un `throw` *sincrono* della funzione sfuggirebbe alla catena di Promise e andrebbe gestito con un `try/catch` separato attorno alla chiamata — una doppia gestione degli errori che `Promise.try` elimina. Accetta anche argomenti da passare alla funzione (`Promise.try(fn, arg1, arg2)`).

## Nota di dettaglio

L'edizione include anche una correzione semantica minore, senza nuova sintassi: le variabili `var` introdotte da un `eval()` a livello **globale** diventano **ridichiarabili**, allineando il comportamento a quello delle normali `var` globali. È un aggiustamento di conformità che non ha impatto pratico nel codice quotidiano.

## ⚡ Ripasso veloce

```js
/* ITERATOR HELPERS — lazy, anche su iteratori infiniti */
gen().map(f).filter(g).take(3).toArray();
Iterator.from(iterable).map(...).toArray();
// lazy: map/filter/take/drop/flatMap · consumo: reduce/toArray/forEach/some/every/find

/* SET — operazioni insiemistiche (nuovo Set o booleano) */
a.union(b);  a.intersection(b);  a.difference(b);  a.symmetricDifference(b);
a.isSubsetOf(b);  a.isSupersetOf(b);  a.isDisjointFrom(b);

/* IMPORT ATTRIBUTES + JSON MODULES (with, non assert) */
import cfg from "./config.json" with { type: "json" };
await import("./d.json", { with: { type: "json" } });

/* RegExp.escape — input sicuro nelle regex dinamiche */
new RegExp(RegExp.escape(inputUtente));

/* RegExp — modificatori inline (i, m, s) e nomi duplicati in alternative */
/(?i:ciao)/;   /(?<a>\d{4})-\d\d|\d\d-(?<a>\d{4})/;

/* FLOAT16 */
new Float16Array([1.5]);  Math.f16round(x);  dv.getFloat16(0);

/* Promise.try — uniforma sync/async/throw in una Promise */
Promise.try(fn, ...args).then(ok).catch(err);
```

## Oltre ES2025

Il ciclo annuale non si ferma. Alla data di scrittura di questa nota, tra le proposte già finalizzate ma attribuite a **edizioni successive** — quindi non ancora parte di ES2025 — figurano: `Math.sumPrecise`, `Error.isError`, `Array.fromAsync`, la conversione `Uint8Array` ↔ Base64/Hex (ES2026); e più avanti `Temporal` (la nuova API per date e orari, destinata a rimpiazzare `Date`), l'*Explicit Resource Management* con `using` e `await using`, e `Iterator.zip` (attribuiti a ES2027). Verranno documentati quando raggiungeranno un'edizione stabile e un supporto diffuso.

## Domande

<details>
<summary>Qual è il vantaggio degli iterator helper rispetto ai metodi degli array?</summary>

La **valutazione pigra** (lazy). I metodi degli array (`map`, `filter`, ecc.) sono *eager*: ciascuno percorre l'intero array e produce un nuovo array intermedio completo prima che il metodo successivo inizi. Su sorgenti grandi questo spreca memoria, e su sorgenti **infinite** (un generator che non termina) è semplicemente impossibile. Gli iterator helper elaborano invece un elemento alla volta, su richiesta, propagandolo lungo l'intera catena senza materializzare array intermedi: `naturali().map(f).filter(g).take(3)` calcola esattamente gli elementi necessari a produrre i primi tre risultati, poi si ferma. La materializzazione avviene solo a fine catena, con un metodo di consumo come `toArray()`. In più, gli helper funzionano su qualsiasi iterator (generator, `Map.keys()`, ecc.), non solo sugli array.

</details>

<details>
<summary>Perché i moduli JSON richiedono l'attributo <code>with { type: "json" }</code> ed è obbligatorio?</summary>

Per ragioni di **sicurezza**. Senza una dichiarazione esplicita del tipo, il browser dovrebbe fidarsi del `Content-Type` restituito dal server o dall'estensione del file per decidere come interpretare la risorsa importata. Un server compromesso o mal configurato potrebbe servire codice JavaScript eseguibile al posto di quello che ci si aspetta essere dati JSON inerti, ottenendo esecuzione di codice arbitrario. L'attributo `with { type: "json" }` rende l'intenzione parte del codice sorgente: il runtime **verifica** che la risorsa sia effettivamente JSON e la tratta come dati, rifiutando qualsiasi altra cosa. La dichiarazione è obbligatoria proprio perché la sua assenza reintrodurrebbe il rischio. La sintassi con `with` sostituisce la precedente proposta `assert`, che è stata ritirata.

</details>

<details>
<summary>Che problema risolve <code>RegExp.escape()</code>?</summary>

Risolve l'inserimento sicuro di una stringa arbitraria come testo **letterale** dentro una regex costruita a runtime. Quando si interpola input (specialmente non fidato) in `new RegExp(...)`, ogni metacarattere presente nella stringa viene interpretato come sintassi regex: un `.` matcherebbe qualsiasi carattere, un `*` diventerebbe un quantificatore, parentesi non bilanciate causerebbero un errore di sintassi. Nel migliore dei casi si ottengono match errati; nel peggiore, si apre la porta a una ReDoS (denial of service tramite regex catastrofiche). `RegExp.escape(str)` neutralizza tutti i caratteri speciali anteponendo il backslash, così la stringa viene cercata esattamente com'è. Prima esisteva solo la ricetta manuale `str.replace(/[.*+?^${}()|[\]\\]/g, "\\$&")`, facile da copiare in modo incompleto; `RegExp.escape` è la versione ufficiale, completa e corretta.

</details>

<details>
<summary>In cosa <code>Promise.try()</code> differisce dal semplice chiamare la funzione dentro un <code>.then()</code>?</summary>

`Promise.try(fn)` esegue `fn` **immediatamente** e ne cattura l'esito in una Promise, gestendo in modo uniforme tre casi: se `fn` restituisce un valore, la Promise si fulfilla con quel valore; se restituisce una Promise, la adotta; se **lancia** un'eccezione in modo sincrono, la Promise si rigetta con quell'errore. Il valore aggiunto sta proprio nell'ultimo caso: se si chiamasse `fn` direttamente (ad esempio `Promise.resolve(fn())`), un `throw` sincrono di `fn` avverrebbe *prima* che la Promise venga creata, sfuggendo alla catena `.catch()` e richiedendo un `try/catch` separato attorno alla chiamata. `Promise.try` racchiude l'invocazione in modo che anche gli errori sincroni finiscano nella catena, permettendo un'unica gestione degli errori con `.catch()` a prescindere dal fatto che `fn` sia sincrona, asincrona, o fallisca subito.

</details>
