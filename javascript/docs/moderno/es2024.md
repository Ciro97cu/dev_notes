## `Object.groupBy()` e `Map.groupBy()`

Raggruppano gli elementi di un iterable in base al valore restituito da una funzione di classificazione. È un'operazione tra le più richieste nella manipolazione dei dati, che prima richiedeva un `reduce()` verboso o una libreria esterna (il `groupBy` di Lodash).

`Object.groupBy(items, fn)` restituisce un **oggetto** (senza prototype, `null`-prototype) le cui chiavi sono le categorie prodotte dalla funzione:

```js
const numeri = [1, 2, 3, 4, 5, 6];

Object.groupBy(numeri, n => n % 2 === 0 ? "pari" : "dispari");
// { dispari: [1, 3, 5], pari: [2, 4, 6] }

const persone = [
    { nome: "Anna", reparto: "IT" },
    { nome: "Bruno", reparto: "HR" },
    { nome: "Carla", reparto: "IT" },
];
Object.groupBy(persone, p => p.reparto);
// { IT: [{Anna}, {Carla}], HR: [{Bruno}] }
```

`Map.groupBy(items, fn)` fa lo stesso ma restituisce una **`Map`**, così le chiavi possono essere di **qualsiasi tipo** (anche oggetti), non solo stringhe/Symbol:

```js
const perParità = Map.groupBy(numeri, n => n % 2);
perParità.get(0);   // [2, 4, 6]
perParità.get(1);   // [1, 3, 5]
```

La regola di scelta: `Object.groupBy` quando le categorie sono stringhe (il caso comune), `Map.groupBy` quando la chiave di raggruppamento è un oggetto o serve preservare l'ordine di inserimento delle chiavi.

## `Promise.withResolvers()`

Restituisce in un colpo solo una Promise **insieme** alle sue funzioni `resolve` e `reject`, estratte all'esterno del costruttore.

```js
const { promise, resolve, reject } = Promise.withResolvers();

/* resolve e reject sono ora disponibili qui fuori */
someEmitter.on("done", (val) => resolve(val));
someEmitter.on("error", (err) => reject(err));

await promise;
```

Prima bisognava dichiarare due variabili esterne e "catturarle" dentro l'executor, un idioma ripetitivo:

```js
/* pattern precedente, verboso */
let resolve, reject;
const promise = new Promise((res, rej) => { resolve = res; reject = rej; });
```

È particolarmente utile quando la risoluzione avviene in risposta a eventi esterni o callback che non sono contenuti nel corpo dell'executor — per esempio quando si "promisifica" un'API basata su eventi.

## ArrayBuffer ridimensionabili e trasferibili

Due proposte estendono il controllo sulla memoria dei buffer visti nel capitolo [Collezioni](/docs/libro6/05-collezioni.md).

Un `ArrayBuffer` può ora essere dichiarato **ridimensionabile**, indicando una dimensione massima; il metodo `.resize()` ne cambia la lunghezza fino a quel massimo, senza doverne allocare uno nuovo e copiare.

```js
const buf = new ArrayBuffer(8, { maxByteLength: 16 });
buf.resizable;      // true
buf.maxByteLength;  // 16
buf.resize(16);     // ora è lungo 16 byte
```

Il `SharedArrayBuffer`, che per sicurezza non può rimpicciolirsi, ha l'analogo `.grow()` (solo crescita) e la proprietà `.growable`.

Il metodo `.transfer()` **trasferisce** la proprietà della memoria a un nuovo `ArrayBuffer`, lasciando l'originale in stato *detached* (staccato, inutilizzabile) — la controparte lato JavaScript del trasferimento zero-copia che già avveniva con i Transferable Objects nei Web Worker.

```js
const originale = new ArrayBuffer(8);
const nuovo = originale.transfer();   // sposta la memoria
originale.detached;   // true — l'originale è ora staccato
```

## RegExp: flag `v` (set notation e proprietà di stringhe)

Il flag `v` (*unicodeSets*) è una versione potenziata del flag `u`, con due capacità nuove nelle classi di caratteri:

- **Operazioni insiemistiche** dentro `[...]`: differenza `--` e intersezione `&&`.
- **Proprietà Unicode di stringhe** con `\p{...}`, cioè property che matchano *sequenze* di più code point (non solo singoli caratteri).

```js
/* differenza: lettere greche TRANNE le minuscole */
/[\p{Script=Greek}--\p{Lowercase}]/v.test("Ω");   // true
/[\p{Script=Greek}--\p{Lowercase}]/v.test("ω");   // false

/* intersezione: cifre che sono anche ASCII */
/[\p{Decimal_Number}&&\p{ASCII}]/v.test("7");     // true

/* proprietà "di stringa": emoji composti da più code point */
/^\p{RGI_Emoji}$/v.test("👨‍👩‍👧");                    // true (emoji famiglia)
```

`v` e `u` sono mutuamente esclusivi: si usa l'uno o l'altro. `v` è il più espressivo ed è la scelta consigliata per il nuovo codice che lavora con Unicode.

## `Atomics.waitAsync()`

Variante **non bloccante** di `Atomics.wait()` (visto in [ES2017](es2017.md)). Invece di bloccare il thread finché un valore in memoria condivisa cambia, restituisce un oggetto con una Promise che si risolve alla notifica — permettendo così di attendere sulla memoria condivisa anche dal **thread principale**, dove `Atomics.wait()` (bloccante) è vietato perché congelerebbe la UI.

```js
const ta = new Int32Array(new SharedArrayBuffer(4));

const { async, value } = Atomics.waitAsync(ta, 0, 0);
if (async) {
    value.then((esito) => {
        // "ok" quando un altro agente chiama Atomics.notify(ta, 0)
    });
}
```

## Stringhe Unicode ben formate: `isWellFormed()` / `toWellFormed()`

Le stringhe JS sono sequenze di code unit UTF-16 e possono contenere *lone surrogate* (metà di una coppia surrogata non accoppiata), risultando **mal formate** rispetto a Unicode. Questo causa errori quando si passano a API che richiedono UTF-8 valido (per esempio `encodeURIComponent` o l'invio in rete). Due nuovi metodi permettono di verificare e sanare:

```js
"abc".isWellFormed();          // true
"ab\uD800".isWellFormed();     // false — surrogate isolato

"ab\uD800".toWellFormed();     // "ab�" — sostituisce con U+FFFD (replacement char)
```

`toWellFormed()` rimpiazza ogni lone surrogate con il carattere di sostituzione `U+FFFD` (�), producendo una stringa sempre codificabile senza errori.

## Ripasso veloce

```js
/* RAGGRUPPAMENTO */
Object.groupBy(items, x => categoria(x)); // → oggetto null-prototype, chiavi stringa
Map.groupBy(items, x => oggettoChiave);    // → Map, chiavi di qualsiasi tipo

/* PROMISE.WITHRESOLVERS — resolve/reject estratti fuori */
const { promise, resolve, reject } = Promise.withResolvers();

/* ARRAYBUFFER */
new ArrayBuffer(8, { maxByteLength: 16 }).resize(16);
buf.transfer();   // sposta la memoria; originale → detached

/* REGEXP flag v — set notation + proprietà di stringhe */
/[\p{Script=Greek}--\p{Lowercase}]/v;   // differenza
/[\p{Decimal_Number}&&\p{ASCII}]/v;     // intersezione

/* ATOMICS.WAITASYNC — attesa non bloccante (anche sul main thread) */
Atomics.waitAsync(ta, 0, 0).value.then(...);

/* UNICODE BEN FORMATO */
"ab\uD800".isWellFormed();   // false
"ab\uD800".toWellFormed();   // "ab�"
```

## Domande

<details>
<summary>Quando conviene <code>Map.groupBy()</code> invece di <code>Object.groupBy()</code>?</summary>

La differenza è il tipo della struttura restituita e, di conseguenza, il tipo ammesso per le chiavi di raggruppamento. `Object.groupBy()` restituisce un oggetto semplice (con prototype `null`), le cui chiavi sono necessariamente stringhe o Symbol: è la scelta naturale quando si raggruppa per una categoria testuale (`"pari"`/`"dispari"`, un nome di reparto, ecc.). `Map.groupBy()` restituisce una `Map`, quindi le chiavi possono essere di **qualsiasi tipo**, inclusi oggetti, con identità per riferimento — utile quando la classificazione produce come chiave un oggetto (per esempio raggruppare elementi per l'oggetto-categoria a cui appartengono). La `Map` inoltre preserva esplicitamente l'ordine di inserimento delle chiavi e offre l'API `get`/`has`/`size`. Si usa `Object.groupBy` per il caso comune con chiavi stringa, `Map.groupBy` quando la chiave non è una stringa o serve la semantica della `Map`.

</details>

<details>
<summary>Che problema risolve <code>Promise.withResolvers()</code>?</summary>

Risolve la scomodità di dover risolvere o rigettare una Promise da **fuori** del suo executor. Il costruttore `new Promise(executor)` espone `resolve` e `reject` solo come argomenti dell'executor, quindi quando la risoluzione dipende da un evento esterno (un listener, un callback di un'API basata su eventi) bisognava dichiarare due variabili nello scope esterno e catturarle dentro l'executor — un idioma ripetitivo e poco leggibile. `Promise.withResolvers()` restituisce direttamente `{ promise, resolve, reject }`, mettendo le tre parti sullo stesso piano e a disposizione nello scope corrente. È l'ideale per promisificare sorgenti event-driven, dove il momento della risoluzione non è contenuto in un blocco di codice sincrono.

</details>

<details>
<summary>Cosa aggiunge il flag <code>v</code> delle regex rispetto al flag <code>u</code>?</summary>

Il flag `v` (unicodeSets) è un superset di `u` con due capacità aggiuntive dentro le classi di caratteri `[...]`. Primo, le **operazioni insiemistiche**: la differenza `[A--B]` (i caratteri di A che non sono in B) e l'intersezione `[A&&B]` (i caratteri presenti sia in A sia in B), che permettono di comporre classi complesse in modo dichiarativo invece che con lookahead/lookbehind. Secondo, le **proprietà Unicode di stringhe**: alcuni `\p{...}` (come `\p{RGI_Emoji}`) matchano sequenze di più code point, non solo singoli caratteri — necessario per gestire correttamente gli emoji composti (bandiere, famiglie, modificatori di tono della pelle) che occupano più code point. `v` e `u` non possono coesistere sulla stessa regex; per il nuovo codice Unicode-aware si preferisce `v`.

</details>

<details>
<summary>Perché serve <code>Atomics.waitAsync()</code> se esiste già <code>Atomics.wait()</code>?</summary>

Perché `Atomics.wait()` è **bloccante**: sospende completamente il thread finché il valore in memoria condivisa non cambia (o scade il timeout). Questo è accettabile in un Web Worker, ma è **vietato sul thread principale** del browser, perché bloccarlo congelerebbe l'intera interfaccia utente (nessun rendering, nessun input). `Atomics.waitAsync()` fornisce l'attesa in forma **non bloccante**: invece di fermare il thread, restituisce una Promise che si risolve quando arriva la notifica (`Atomics.notify`). Così anche il thread principale può "attendere" un cambiamento sulla memoria condivisa in modo asincrono, integrandosi con l'event loop senza congelare la UI. È il ponte tra la sincronizzazione a memoria condivisa e il modello asincrono basato su Promise.

</details>
