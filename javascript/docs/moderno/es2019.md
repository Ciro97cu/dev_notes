# ES2019 (ES10)

La decima edizione è fatta di aggiunte piccole ma di uso quotidiano: appiattimento degli array (`flat`/`flatMap`), la conversione inversa da coppie a oggetto (`Object.fromEntries`), il trim direzionale, e alcune garanzie della specifica rese finalmente esplicite (ordinamento stabile, `catch` senza binding).

---

## `Array.prototype.flat()` e `flatMap()`

`flat()` restituisce un nuovo array in cui gli array annidati sono stati "appiattiti" fino a una profondità data (default `1`).

```js
[1, [2, 3], [4, [5, 6]]].flat();       // [1, 2, 3, 4, [5, 6]]
[1, [2, [3, [4]]]].flat(2);            // [1, 2, 3, [4]]
[1, [2, [3, [4]]]].flat(Infinity);     // [1, 2, 3, 4] — appiattimento totale
```

Come effetto collaterale utile, `flat()` **rimuove gli slot vuoti** degli array sparsi:

```js
[1, , 3].flat();   // [1, 3]
```

`flatMap()` è la combinazione di `map()` seguito da un `flat(1)`: applica una callback a ogni elemento e appiattisce il risultato di un livello. È l'idioma giusto quando la callback può produrre zero, uno o più elementi per ogni input.

```js
[1, 2, 3].flatMap(n => [n, n * 2]);    // [1, 2, 2, 4, 3, 6]

/* filtro-e-mappa in un colpo: restituire [] scarta l'elemento */
[1, 2, 3, 4].flatMap(n => n % 2 === 0 ? [n] : []); // [2, 4]

/* spezzare frasi in parole */
["ciao mondo", "buongiorno"].flatMap(s => s.split(" "));
// ["ciao", "mondo", "buongiorno"]
```

`flatMap` appiattisce **un solo** livello e non è personalizzabile in profondità; per profondità maggiori si usa `map(...).flat(n)`.

## `Object.fromEntries()`

È l'inverso di `Object.entries()` ([ES2017](es2017.md)): prende un iterable di coppie `[chiave, valore]` e costruisce un oggetto. Chiude il ciclo che rende gli oggetti trasformabili con i metodi degli array.

```js
Object.fromEntries([["a", 1], ["b", 2]]); // { a: 1, b: 2 }

/* trasformare un oggetto: entries → map → fromEntries */
const prezzi = { pane: 2, latte: 1.5 };
const scontati = Object.fromEntries(
    Object.entries(prezzi).map(([k, v]) => [k, v * 0.9])
);
// { pane: 1.8, latte: 1.35 }

/* convertire una Map in oggetto */
Object.fromEntries(new Map([["x", 10], ["y", 20]])); // { x: 10, y: 20 }

/* da URLSearchParams a oggetto */
Object.fromEntries(new URLSearchParams("a=1&b=2")); // { a: "1", b: "2" }
```

Accetta qualsiasi iterable di coppie, quindi funziona direttamente con `Map`, `URLSearchParams` e altre sorgenti che producono entries.

## `String.prototype.trimStart()` e `trimEnd()`

Versioni direzionali di `trim()`: rimuovono lo spazio bianco solo all'inizio o solo alla fine della stringa.

```js
"   ciao   ".trimStart();  // "ciao   "
"   ciao   ".trimEnd();    // "   ciao"
```

Esistono gli alias storici `trimLeft` e `trimRight`, standardizzati per compatibilità con il codice esistente, ma i nomi canonici sono `trimStart`/`trimEnd` (coerenti con `padStart`/`padEnd`).

## Ordinamento stabile garantito

Fino a ES2018 la specifica **non** garantiva che `Array.prototype.sort()` fosse *stabile*, cioè che elementi considerati uguali dal comparatore mantenessero il loro ordine relativo originario. In pratica i motori si comportavano in modo diverso (V8 era stabile solo per array corti). ES2019 rende la **stabilità un requisito**: elementi con chiave di ordinamento identica conservano l'ordine iniziale.

```js
const persone = [
    { nome: "Anna", eta: 30 },
    { nome: "Bruno", eta: 25 },
    { nome: "Carla", eta: 30 },
];

/* ordinando per età, Anna resta garantitamente prima di Carla (stessa età) */
persone.sort((a, b) => a.eta - b.eta);
// Bruno(25), Anna(30), Carla(30)
```

Questo rende affidabili gli ordinamenti multi-criterio applicati in sequenza (prima per un campo, poi per un altro).

## Optional catch binding

Da ES2019 il parametro del `catch` è **facoltativo**: se l'oggetto errore non serve, si può omettere la parentesi.

```js
/* prima: parametro obbligatorio anche se inutilizzato */
try { rischioso(); } catch (err) { fallback(); }

/* ora: catch senza binding */
try { rischioso(); } catch { fallback(); }
```

Utile quando conta solo *sapere* che qualcosa è fallito, non *perché* — per esempio in un feature test o in un tentativo con fallback.

## `Symbol.prototype.description`

Un getter di sola lettura che espone la **descrizione** con cui un Symbol è stato creato, senza doverla estrarre dalla rappresentazione `Symbol(...)` prodotta da `toString()`.

```js
const s = Symbol("mio identificatore");

s.toString();    // "Symbol(mio identificatore)"
s.description;   // "mio identificatore" — solo la descrizione, pulita

Symbol().description; // undefined — nessuna descrizione fornita
```

## Aggiustamenti minori

Tre revisioni di dettaglio completano l'edizione:

- **`Function.prototype.toString()` rivisto**: ora la specifica impone che restituisca **esattamente** il testo sorgente della funzione così come scritto, commenti e spaziatura inclusi (per le funzioni definite dall'utente); per le funzioni native restituisce la forma standardizzata con `[native code]`.
- **JSON come superset di ECMAScript**: i caratteri di separazione di riga `U+2028` (LINE SEPARATOR) e `U+2029` (PARAGRAPH SEPARATOR) sono ora ammessi **non-escaped** nelle stringhe literal JS. Prima causavano un errore di sintassi, il che impediva a JavaScript di essere un vero superset di JSON (dove quei caratteri sono legali).
- **`JSON.stringify()` well-formed**: i *lone surrogate* (metà di una coppia surrogata UTF-16 non accoppiata) vengono ora emessi come escape sequence `\uXXXX` invece che come caratteri malformati, così l'output di `JSON.stringify` è sempre UTF-8 valido.

```js
JSON.stringify("\uD800");   // '"\\ud800"' — surrogate isolato, escapato correttamente
```

## ⚡ Ripasso veloce

```js
/* ARRAY */
[1, [2, [3]]].flat();          // [1, 2, [3]]  (default depth 1)
[1, [2, [3]]].flat(Infinity);  // [1, 2, 3]
[1, 2].flatMap(n => [n, n]);   // [1, 1, 2, 2]  (map + flat(1))
arr.sort(cmp);                 // ordinamento ora garantito STABILE

/* OGGETTI */
Object.fromEntries([["a", 1]]);          // { a: 1 }  — inverso di entries
Object.fromEntries(new Map([["x", 1]])); // da Map a oggetto

/* STRINGHE */
"  x  ".trimStart();  // "x  "
"  x  ".trimEnd();    // "  x"

/* SINTASSI */
try { f(); } catch { /* niente binding */ }

/* SYMBOL */
Symbol("id").description;   // "id"
```

## Domande

<details>
<summary>Qual è la relazione tra <code>flatMap()</code> e <code>map()</code> + <code>flat()</code>?</summary>

`arr.flatMap(fn)` è esattamente equivalente a `arr.map(fn).flat(1)`: applica la callback a ogni elemento e poi appiattisce il risultato di **un solo** livello. Il caso d'uso tipico è quando la callback restituisce un array di lunghezza variabile per ciascun input: restituendo `[a, b]` si espande un elemento in due, restituendo `[]` lo si scarta (ottenendo un filtro-e-mappa combinato). La limitazione è che appiattisce sempre e solo un livello — non accetta un parametro di profondità. Per profondità maggiori occorre `map(...).flat(n)` esplicito. Oltre alla concisione, `flatMap` è anche leggermente più efficiente perché evita di materializzare l'array intermedio annidato.

</details>

<details>
<summary>Come si trasforma un oggetto in un altro oggetto usando <code>Object.entries</code> e <code>Object.fromEntries</code>?</summary>

Gli oggetti non hanno metodi di trasformazione propri (`map`, `filter`), ma gli array sì. Il pattern è un "andata e ritorno": `Object.entries(obj)` converte l'oggetto in un array di coppie `[chiave, valore]`, su cui si applicano i normali metodi degli array (`map` per trasformare valori/chiavi, `filter` per scartare proprietà), e infine `Object.fromEntries(...)` ricostruisce un oggetto dalle coppie risultanti. Per esempio `Object.fromEntries(Object.entries(obj).filter(([k, v]) => v != null))` produce una copia dell'oggetto senza le proprietà nulle. `Object.fromEntries` accetta qualsiasi iterable di coppie, quindi funziona anche direttamente su `Map` e `URLSearchParams`.

</details>

<details>
<summary>Cosa significa che <code>sort()</code> è "stabile" e perché la garanzia ES2019 è importante?</summary>

Un ordinamento è *stabile* quando due elementi che il comparatore considera uguali (restituisce `0`) mantengono nel risultato lo stesso ordine relativo che avevano nell'input. Prima di ES2019 la specifica non lo garantiva, quindi motori diversi — o lo stesso motore su array di lunghezza diversa — potevano riordinare arbitrariamente gli elementi "pari". ES2019 lo rende un requisito. L'importanza pratica sta negli **ordinamenti a più criteri applicati in sequenza**: si può ordinare prima per un campo secondario e poi per uno primario, sapendo che a parità di campo primario l'ordine del secondario viene preservato. Senza stabilità garantita, questa tecnica sarebbe inaffidabile e dipendente dall'implementazione.

</details>

<details>
<summary>Perché è stato utile ammettere <code>U+2028</code> e <code>U+2029</code> non-escaped nelle stringhe JS?</summary>

Perché rende JavaScript un vero superset sintattico di JSON. Nel formato JSON i caratteri `U+2028` (line separator) e `U+2029` (paragraph separator) sono caratteri legali all'interno delle stringhe. In JavaScript, però, fino a ES2018 quegli stessi caratteri erano trattati come terminatori di riga e provocavano un `SyntaxError` se comparivano non-escaped in una string literal. Ciò significava che una stringa JSON valida, incollata dentro il sorgente JS o prodotta da `eval`/costruzioni dinamiche, poteva rompere il parser. ES2019 ammette quei due caratteri nelle string literal, eliminando la discrepanza e garantendo che ogni testo JSON valido sia anche JavaScript valido.

</details>
