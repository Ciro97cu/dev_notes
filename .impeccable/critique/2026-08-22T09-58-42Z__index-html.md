## Design Specificity Verdict

**Authored for this product — not category-interchangeable.** The identity is load-bearing: one per-card `--accent` token threads through five surfaces (hover halo, progress fill+glow, resume tint, search dots, `.card-pct`); a bespoke HTML hero (gradient monogram + wordmark) rather than a generic coverpage; a cross-vault version-cached search palette that only makes sense for this 8-vault hub; and return-visitor features (cross-vault resume, per-card reading %) built around a personal study loop. **Weakest signal: typography** — everything but the wordmark uses the raw `-apple-system` stack with no distinctive scale, so card text reads slightly generic against the otherwise-bespoke chrome.

**Deterministic scan:** `detect.mjs` on `index.html` and `README.md` → exit 0, `[]` (clean, 0 findings). No false positives to triage. The detector targets generic-design "sameness" tells; it did **not** surface the accessibility/contrast/error-recovery issues below (out of its scope), so the design review carries those.

**Visual overlays:** none — no browser-automation tool is exposed this session, so the live-server overlay/injection was skipped (fallback signal). Findings are from source + CSS reasoning; contrast figures are computed, not screen-measured.

## Overall Impression

A genuinely well-built, distinctive hub — the accent-token system and the zero-build command palette (correct combobox/listbox ARIA, `inert` focus trap, focus restore) are craft most hand-rolled versions get wrong. What holds the ceiling down: **the new search toggles are mouse-only**, accent-as-text fails contrast in light mode, and power features (shortcuts, help) are undiscoverable. Biggest single opportunity: make the search palette fully keyboard/SR-operable and give its error/empty states a way out.

## What's Working

1. **The accent token is architecture, not decoration.** One per-card `--accent` re-themes a vault everywhere via `color-mix` (halo, progress fill+glow, resume tint, search dots).
2. **Return-visitor ergonomics are the spine.** Cross-vault "most recent by timestamp" resume + per-card reading % optimize the real loop (return → resume → track).
3. **The ⌘K palette is done right with zero build.** Version-keyed cached index, grouped/colored results, heading deep-links, debounced input, correct combobox/listbox ARIA with `aria-activedescendant`, real `inert` focus trap, scroll-lock, focus restore.

## Priority Issues

### [P1] Search toggles `Aa`/`W`/`.*` are unreachable by keyboard & screen reader
- **What:** In `hub-search.js` the input `keydown` intercepts **Tab** (`e.preventDefault(); move(...)`) to cycle results, so focus never leaves `.dn-pal-input` to reach the `.dn-pal-tog` buttons — and no key activates them. Mouse-only. The button `title`s ("…(Aa)", "…(W)", "…(.*)") even imply a shortcut that doesn't exist. **Introduced by this change.**
- **Why it matters:** Keyboard-only and screen-reader users are functionally locked out of case/word/regex search.
- **Fix:** Bind toggles to keys in the palette (e.g. `Alt+C`/`Alt+W`/`Alt+R`) or a roving-tabindex reachable without stealing Tab; announce via `aria-pressed` + a polite live region.
- **Suggested command:** `$impeccable harden`

### [P1] Accent-as-text fails WCAG contrast in light mode (pre-existing)
- **What:** Raw `--accent` is used as **text/glyph** in `.tile` monogram, `.card-pct` (.74rem/700), `.resume-arrow`. On the near-white card the JS accent `#e6c200` computes to ≈ **1.7:1** (hard fail); Code green ≈3.5:1 and CSS blue fail AA for the small `.card-pct`; Glossario `#78716c` ≈4.5:1 barely passes. Dark mode is fine.
- **Why it matters:** The "JS" monogram and reading-% label are effectively illegible for low-vision users in light mode.
- **Fix:** Derive `--accent-text` per card (e.g. `color-mix(in srgb, var(--accent) 70%, var(--fg))`) for any text/glyph; reserve raw accent for fills/borders/dots.
- **Suggested command:** `$impeccable colorize`

### [P2] Near-zero on-page discoverability for shortcuts and the two floating buttons
- **What:** `t`/`d`/`?`/`/` exist but nothing visible advertises them; `?` help is itself gated behind pressing `?`. `#theme-toggle` and `#hub-data-btn` are icon-only 44px circles labeled only via `title`; the database glyph doesn't read as "back up / sync your reading data."
- **Why it matters:** First-timers never find power features; the data button is opaque exactly when trust matters (it touches all local data).
- **Fix:** A persistent tiny "?" affordance (or a one-line kbd legend in the footer) opening the existing modal; clearer data icon or a dismissible first-run tooltip.
- **Suggested command:** `$impeccable onboard`

### [P2] The 8-card grid is a flat, unchunked decision point
- **What:** `<main class="grid">` renders all 8 vaults as one uniform group, no labels/sub-grouping (fails the ≤4-per-group and chunking checks).
- **Why it matters:** 8 equally-weighted choices exceed the comfortable chunk and give no semantic scent (language vs tool vs reference); scales badly as the hub grows.
- **Fix:** Lightweight group headings — e.g. *Linguaggi* (HTML/CSS/JS/TS/Angular), *Strumenti* (Git), *Fondamenti & riferimento* (Code/Glossario) — keeping each sub-group ≤5.
- **Suggested command:** `$impeccable layout`

### [P3] Search empty/error states dead-end without recovery
- **What:** `render()` sets "Nessun risultato per «…»." and "Espressione regolare non valida." as terminal status — no next action, and the regex error never points at the active `.*` toggle that caused it.
- **Why it matters:** The search feature's *end* memory is a wall; the regex case forces self-diagnosis of a toggle the user may have forgotten is on.
- **Fix:** On no-results with any toggle on, offer "rimuovi i filtri"; on invalid regex, highlight `.dn-pal-tog[data-t="regex"]` and offer to disable it.
- **Suggested command:** `$impeccable clarify`

## Persona Red Flags (primary action: find & open a note)

- **Jordan (first-timer):** core path fine (cards obviously clickable, clear placeholder); fails on the two unlabeled top-right circles, the unexplained `Aa`/`W`/`.*` trio, the terminal "Nessun risultato" after a typo, and never discovering `?`.
- **Alex (power user):** mostly delighted (⌘K/`/`, ↑↓/↵, regex/word/case, resume, deep-links); the toggle `title`s imply keyboard toggling but Tab is trapped to the result list with no toggle keys → must drop to mouse for regex, breaking a pure-keyboard flow. No in-place "clear query" (Esc closes the whole palette).
- **Sam (a11y/keyboard/SR):** strong base (real `<a>` cards, combobox/listbox ARIA, `inert` trap, focus restore, labeled buttons, reduced-motion). Fails: (1) toggles keyboard/SR-unreachable [P1]; (2) the `#hub-keyhelp` modal (unlike the palette) doesn't move focus in, isn't `role="dialog"`, isn't `inert`-guarded, no labeled close; (3) low-contrast accent text [P1]; (4) floating buttons style `:hover` but not `:focus-visible`.

## Minor Observations

- `.resume-banner` is an `<a>` with no initial `href` until JS sets it (stray non-navigable anchor pre-JS).
- The search pill `kbd` is hard-coded `⌘K`, rewritten to `Ctrl K` by JS on non-Mac — a brief wrong-glyph flash is possible before `init()`.
- Destructive import/QR "replace all" uses a `confirm` where **Cancel performs the destructive action** — inverted phrasing.
- Theme toggle shows the target mode's icon (moon while light) — occasionally confusing; `title` mitigates.
- Two mystery circles compete for the same top-right corner.

## Questions to Consider

1. If the resume banner is the highest-value element for a returning studier, why does it sit below the search pill rather than being promoted to the hero for anyone with reading history?
2. The palette can regex-search all 8 vaults, yet the landing's primary affordance is a wall of cards. As content only grows, should the hub go **search-first** with the grid demoted to a fallback?
3. Who does the `Aa`/`W`/`.*` power-triad actually serve on a *personal* notes hub — and does its discoverability + keyboard-a11y cost justify it over one forgiving fuzzy match?
